# 아이디어 메모

처음에 브레인스토밍한 아이디어 목록입니다. `skills/*/SKILL.md`는 이 메모를 바탕으로 썼습니다.

## Ⅰ. 문제 정의

1. 게임 숏츠를 기획할 때 "요즘 뭐가 터지는지"를 감으로 고르게 된다.
2. 인기 영상의 댓글에는 시청자가 좋아한 장면, 궁금한 점, 다음에 보고 싶은 영상이 그대로 적혀 있다.
3. 댓글을 사람이 다 읽기는 어렵다. 그래서 역할별 에이전트가 모으고, 나누고, 아이디어로 묶고, 검수해서 기획안으로 정리하게 한다.

## Ⅱ. 플랫폼별 수집 방법

1. 유튜브 쇼츠: YouTube Data API로 공개 영상 댓글을 자동 수집할 수 있다.
2. 인스타그램 릴스: 공식 API는 내 계정 게시물 댓글만 준다. 다른 사람 릴스 반응은 CSV로 넣는다.
3. 틱톡: CSV로 넣는다.

## Ⅲ. 에이전트별 기준 아이디어

### 1. collector (수집)
1. 최근 7일 안에 올라온 게임 숏츠 중 조회수나 좋아요가 높은 영상을 고른다.
2. 같은 게임 영상을 2개 이상 모아야 반응을 비교할 수 있다.
3. 영상마다 좋아요가 많은 댓글부터 50개 정도 가져온다.
4. 이모지만 있거나 3자 미만인 댓글은 개수만 세고 분석에서는 뺀다.

### 2. classifier (분류)
"내 숏츠에 써먹을 수 있는 반응인가"를 기준으로 나눈다.

1. 터진 장면: 특정 장면이나 순간을 말하는 댓글. 타임스탬프가 있으면 거의 확실하다.
2. 게임 관심: 게임 이름, 플랫폼, 하는 방법을 묻는 댓글. 그 게임 자체에 수요가 있다는 신호다.
3. 요청: 다른 게임, 2편, 다른 모드를 해 달라는 댓글. 아직 아무도 안 만든 주제일 수 있다.
4. 불만: 너무 길다, 자막이 안 보인다, 낚시 썸네일이다. 내 영상에서 피할 점이다.
5. 단순 반응: "재밌어요"처럼 구체적인 내용이 없는 댓글.
6. 스팸: 링크, 맞팔, 부업 홍보.

우선순위 아이디어는 이렇다.
1. 1순위: 장면이나 게임을 콕 집었고 좋아요가 많은 댓글.
2. 2순위: 요청과 불만. 여러 댓글에서 반복되면 올린다.
3. 3순위: 단순 반응.

### 3. planner (기획)
1. 같은 게임, 같은 유형의 반응이 여러 개 모이면 아이디어 하나로 만든다.
2. 아이디어마다 제목, 첫 3초 훅, 근거 댓글을 적는다.
3. 원본 영상의 구성을 그대로 따라 하지 않는다. 반응이 좋았던 이유만 가져온다.
4. 요청 댓글에서 나온 주제는 "아직 없는 영상" 후보로 표시한다.

### 4. reviewer (검수)
1. 원본 영상 제목과 거의 같으면 수정을 요청한다.
2. 근거 댓글이 1개뿐이면 수정을 요청한다.
3. 숏츠 제목이 너무 길면 줄이라고 한다.
4. 내가 직접 플레이하거나 녹화할 수 없는 게임이면 사람 확인으로 넘긴다.

### 5. reporter (정리)
1. 아이디어를 근거 댓글 좋아요 합계 순으로 정리한다.
2. 기획안에 반복 키워드와 피할 점(불만 댓글)도 같이 적는다.

## Ⅳ. 확장 아이디어

1. 매주 월요일 자동 실행해서 주간 기획안 만들기.
2. 반복 키워드를 모아 keyword 분석 프로젝트와 연결하기.

## Ⅴ. 자동 답글 모드 아이디어

내 계정에 달린 댓글은 직접 답해야 하는데, 플랫폼이 세 개라 놓치기 쉽다. 그래서 처음 만든 인스타 답글 구조를 유튜브·인스타·틱톡으로 넓힌다.

### 1. 플랫폼별로 할 수 있는 것
1. 유튜브: 댓글 읽기는 API 키로 된다. 답글 달기와 숨기기는 채널 주인의 OAuth 토큰이 필요하다.
2. 인스타그램: 내 게시물 댓글 읽기, 답글, 숨기기가 Graph API로 된다.
3. 틱톡: 일반 개발자용 공개 API로는 댓글 답글이 안 된다. 답글 목록을 CSV로 저장해서 앱에서 붙여넣는다.

### 2. reply_classifier (분류)
1. 질문, 칭찬, 불만, 협업, 스팸, 기타로 나눈다.
2. 협업 제안과 강한 불만은 우선순위 1로 둔다.

### 3. responder (답글)
1. 플랫폼마다 안내할 곳이 다르다. 유튜브는 설명란, 인스타는 캡션, 틱톡은 고정 댓글.
2. 다음 영상 날짜처럼 지킬 수 없는 약속은 하지 않는다.
3. 짧게 쓴다. 숏츠 댓글은 한두 문장이면 충분하다.

### 4. moderator (검수)
1. 너무 길면 줄이라고 돌려보낸다.
2. 협업 제안, 환불이나 신고 같은 민감한 말은 사람이 확인한다.

### 5. publisher (게시)
1. 처음에는 dry-run으로 두고 며칠 결과를 본 뒤 실제 게시를 켠다.
2. 스팸은 지우지 않고 숨긴다. 잘못 분류했을 때 되돌릴 수 있게 하기 위해서다.
